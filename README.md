# @petercjl/cloud-hug-style-transfer

将整理好的商品实拍或旧详情页升级到内置新版模板，先生成各款色产品设定卡，再建立独立的人货比例依据，集中确认产品外观、独立尺度、四宫格内容及整套范围后，自动规划每屏一个方案并连续生成每屏一张完整无字页面。中文展示名为“抱抱云朵社品牌升级”；包名、Skill 名称和安装更新入口继续使用 `cloud-hug-style-transfer`。

面向具备所需执行能力的任意 Agent；Node.js 22+。当前 Agent 识别自己的 Skill 目录、能力与注册方式。

## 安装

把下面这句话发送给当前 Agent：

> 请安装 npm 包 @petercjl/cloud-hug-style-transfer。

安装同时包含工具、完整 Skill 和独立运行依赖。Agent 核验本地入口、文件与版本，再确认宿主能发现 Skill。生图还需要当前宿主已安装并配置的 `@petercjl/toapiscli` >=0.1.1，直接复用其凭据。

当前仓库 0.7.0 已迁移 ToAPIs；提交 GitHub 不代表已经发布 npm。安装本次仓库修订时，在已核验的仓库目录执行 `npm ci --ignore-scripts`，再执行 `node npm/cli.mjs skill install --agent workbuddy --path EXACT_SKILL_DIR --json`。Agent 解析自己的实际技能目录，并核验其发现状态；不要用尚未更新的 npm 版本替代本次修订。

## 更新

> 请更新 npm 包 @petercjl/cloud-hug-style-transfer。

每次更新只处理明确选中的当前 Agent，保留自定义元数据与更新前备份。同版本也会检查和修复 Skill。自动检测默认提示；自动安装需要单独授权。

## 使用

附上已整理好的多角度商品实拍、旧详情页或两者组合，以及本次特殊要求。旧资料没有可靠的人与产品同框图时，补充一张表达产品相对大小的实拍；已有明确尺寸直接提取。

> 请使用 cloud-hug-style-transfer，将所附商品资料升级到内置新版模板，先准备产品卡与独立人货比例依据，集中确认外观、尺度、四宫格内容和整套范围后，自动规划每屏一个方案并连续生成每屏一张完整无字页面。

新版流程以新版模板为起点：01、02、16–19 跳过；03–15 按各屏职责规划，其中 07–10 按确认的产品形态分组调整页数，12 按确认卖点安排四格。产品卡、尺度依据、四宫格内容与整套生成范围在前期集中确认，已有答案和授权直接沿用；后续规划是 Agent 的执行依据，默认不再要求选稿或逐批确认。

产品卡负责外观，独立同框照片负责人与产品的相对大小；不把比例图拼进产品卡，也不要求逐卡配套。同形态同规格的配色可以共用比例照片，规划、实际生图输入与成图验收均使用本轮尺度图；已有适用图不再追问厘米或编写身体／家具比例。详见 [产品尺度与人货比例](skills/cloud-hug-style-transfer/references/product-scale.md)。

每次详情生成实际传入对应屏品牌案例，同时继承版式、白色概念棚景、浅蓝承托、少量设计感木件与柔光。文字说明参考职责和本屏任务；逐格验收品牌与尺度，不以版式、无字或外观正确替代。

默认每屏一个方案、一次生成一张完整无字页面，三图或四宫格的全部图片位在同一张页内呈现。单形态商品为 10 张详情图，产品卡另计；已有合格卡片直接复用。A/B/C、先试几张、先审规划和按格拆图仅在用户明确要求时启用。分批生成属于内部调度，批次结束自动继续剩余已授权项。只保存图片、原任务记录和对应清单，确认与生成状态统一维护在 manifest.json。

媒体入口来自当前宿主 `toapiscli` Skill 的 `.runtime/dist/cli.mjs`。默认使用 `gpt-image-2.6-sunburst`、2K，按完整模板页选择实际支持的比例，明确拆图时再按图片位选择；执行前读取当前模型文档，用户指定模型优先。状态未知时使用原任务目录恢复，不自动重复提交付费任务。详见 [媒体执行](skills/cloud-hug-style-transfer/references/media-execution.md)。

本次业务规则来自 `cloud-hug-brand-upgrade` 1.1.0（2026-10-27），已替换原逐张源页风格转换流程；来源记录见 [PROVENANCE.json](skills/cloud-hug-style-transfer/PROVENANCE.json)。原始素材保留，历史名称用于兼容已有安装。

账号、服务访问与付费生成按各自授权执行。安装不授予服务权限。
