# 数量、状态与交付

只为当前任务建需要的目录：原文件保持在其位置，项目内可用 `prepared/` 保存长图与分屏，`prompts/` 保存每屏提示词，`generated/` 保留媒体原始输出，`final/` 放通过验收的每屏一张图。已经分屏时可直接引用输入，不为凑目录复制原件。用户明确指定目录就按其要求；否则在本轮工作目录创建新项目目录，不依赖作者的盘符。

分屏成功后建立 `progress.json` 或等价本地记录。最小必要字段：

| 层级 | 字段 |
| --- | --- |
| 本轮 | run_id、输入类型、分屏清单路径、授权屏号列表、预期张数 |
| 单屏 | page_id、原图路径与 SHA-256、width/height、提示词路径、实际参考顺序与职责、count=1、task_id、输出路径、实测尺寸、文字/版式/产品/人物/棚景逐项验收状态与问题 |
| 可选画板 | canvas_id/url、每屏稳定 row_index、写入状态、next_top |

状态可用 `prepared`、`submitted`、`downloaded`、`qa_passed`、`needs_fix`、`blocked`。只有实际对照通过后才写 `qa_passed`；生成服务成功不等于通过。未生图时 task_id 留空，不能伪造成功回执。记录不含 token、请求头、认证配置、签名密钥或登录信息。

建议成图以原始屏号对应命名，如 `01_抱抱云朵社.png`、`02_抱抱云朵社.png`。用户原文件名能明确对应时也可沿用。重复任务使用新目录，不覆盖以前成图。10 个授权分屏应有 10 个对应结果，不能把一屏内十种颜色拆成十次生图。无文字页面保持无文字；信息表、色卡、首屏、尾屏都按实际内容处理，不按历史模板页码跳过。

最终至少交付：

- 可访问的 `final/` 目录或用户要求的压缩包。
- 简明逐屏对应清单（屏号、原图、成图、尺寸、验收结论）。
- 实际完成数/应完成数，以及仍缺失、未通过或未验证的具体屏。
- 有画板时提供已回读验证的真实链接；无画板不补造链接。

按当前用户已建立的缓存约定保存生成结果副本，保留原始输出。当前用户另有要求时按其要求；本包不把 `E:` 等私人盘符设为所有宿主默认值。

文字局部恢复、等比尺寸整理属于同张图的后处理，最终仍只交一张选定图；中间结果留在 generated 或工作目录。修复不能带回旧墙窗、拉伸产品或改变版式与裁切。新付费生成是新的尝试，需要依实际授权判断，不能将“一张最终图”解释成无限尝试预算。
