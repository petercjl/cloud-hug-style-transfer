# 图片与对应清单

文件名保留以兼容旧链接；当前交付只包含图片与对应清单，不使用在线画板或本地 HTML。

在当前项目内保存原始输入、提示词、每次请求目录和结果，不能把创作产物写进 Skill 安装目录。每次生成保留原目录和 CLI 写出的请求、状态与下载文件；另存交付副本时不移动或覆盖原图。

`manifest.json` 包含项目 ID、Skill 工作流修订、媒体包版本、独立 `scale_basis` 记录和 `items` 数组。`scale_basis` 按 [尺度规则](product-scale.md) 保存适用产品／规格、尺度图路径与 SHA-256、来源及限制；已有真实尺寸附出处，未知用 null。不新增估读数字或待确认尺寸表，不按产品卡数量复制或配套。每项生成记录：

- `id`、`stage`（product-card 或 detail）、`page_id`、`template`、`product_group`、`variant`、`direction`、`slot`。
- `promptFile`、`references`（有序数组，每项含 path、sha256、role）、`model`、`parameters`、`taskDirectory`。
- 详情页所用 `scale_basis_ids` 及适用格位，不要求计划身体比例。`references.role` 区分 product-appearance、human-product-scale、model-identity、page-template；page-template 同时负责版式和品牌摄影。每屏记录实际模板文件，不能只写07–10。有序清单、提示词图号与真实请求逐项一致；路径、哈希和实际提交关系可追溯，不把尺度图错标为棚拍图或只登记不提交。
- `generationId`、`taskId`、`status`、`billing`（原回执实际费用；未知用 null）、`outputs`（实际路径、宽高、SHA-256）。
- `review`（pending / pass / needs-fix），保存逐格的具体观察与问题，字段建议见下；`deliveryFiles` 及未完成说明。

不适用的字段用 null；只登记真实文件和返回 ID，不编造链接。模板编号与实际屏序分开记录，产品卡与详情素材分阶段编号。默认每屏唯一方案使用内部方向键 `A`；整页任务按 `page_id + direction` 记录一个输出，`slot` 为 `page`，另记其中的内容格位，不展开成三条或四条生成任务。仅明确拆图时按格位分别记录。验收同时保存品牌案例与尺度图的对照结论；未看清的必要项为 pending，不以外观或版式通过抵消品牌／尺度问题。

恢复时读取原 `taskDirectory`，查询原任务并更新同一清单项；不能另建重复记录掩盖未知或失败状态。最终核对已确认范围、成图数量、文件可读性和美术验收状态，交付图片目录与 `manifest.json`。只生成一部分时继续剩余已授权任务；存在真实阻塞时如实列出，不能把部分交付标成整套完成。

## 逐格验收记录

`review.checks` 按实际格位记录 `slot`、`criterion`、`status`、`reference_ids` 和 `observation`；沿用项目等价字段即可。检查产品外观、尺度一致性、概念棚景、浅蓝承托、适用木件、柔光、页面任务与人物状态，另核对无文字及交付数量。不能所有页面复制同一份通用通过列表。

每个适用项记录看到了什么以及与哪张参考对照。纯微距无环境或无法展示整体尺度时，该项可用 `not-applicable` 并说明景别原因；这不是漏看必要项的通道。发现住宅墙面、该有的浅蓝消失或体量偏离时为 `needs-fix`；未查看／未看清的必要项为 `pending`。任一必要项待核对或需修正，整页不能写 `pass`。整套另记录跨页的产品尺度与品牌一致性，不只核对生成张数。

## 确认与当前状态

以同一个 `manifest.json` 保存当前事实，沿用既有项目的等价字段，不另建互相冲突的第二套状态。新项目至少记录：

- `confirmation`：产品卡的 variant_id、最终路径／版本和确认依据；已确认产品分组；独立尺度记录的 ID、适用规格与已接受限制；四宫格四项任务及其确认依据。区分未确认、已确认、用户授权 Agent 按证据决定，不以空值或旧总览猜测用户同意。已指定适用尺度图直接沿用，不额外创建 size_spec 估读确认或要求补齐厘米数。
- `confirmedScope`：实际页 ID 列表、mode、directions（默认只有 A）、产品卡与详情图分别多少张、generationCount、本轮已授权费用／返工边界，以及用户授权的来源。已存在的整套请求直接复用；仅确认外观不补写为整套授权。
- `plan`：各页唯一方案、格位任务、所用卡片版本／尺度 ID、自检状态与具体阻塞项；默认自检通过即执行，不新增等待用户选案的状态。
- `items`：真实提交、任务状态、下载与验收记录；待执行的页面保留在计划清单中，不伪造生成 ID。

每次收到确认、修改资料、完成规划、提交任务、下载或验收后，更新对应记录和总览的当前进度。历史说明可以保留但明确标为已被后续状态替代，不能仍把已确认四格写成“待确认”、已生成图片写成“尚未生成”。

恢复时先读最新用户要求、上述确认／范围及原任务回执；冲突时核对真实文件和记录来源，仅无法确定的关键事项再问。沿用有效确认，查询进行中或未知的原任务，复用已完成合格输出，再执行尚未提交的已授权页面。不要因为读取了旧三案计划就补生 B/C，也不要因只读数量工具未授予权限而撤销已有授权。

外观存在明显差异、格位任务错误、尺度偏离、住宅化或该有的浅蓝缺失时，对应 `review` 为 `needs-fix`；未实际查看则为 `pending`。只有核对通过才写 `pass`。汇总区分任务提交数、成功下载数、验收通过数和未完成数，不能把服务成功数直接当作验收通过数。
