# 无限画板：逐图左右对照

仅进入生成执行节点时读取。输入是本轮商品/用途、源图与生成计划；输出是一个新建且贴切命名的无限画板文件，每张成图一行，原图在左、成图在右，后续行紧凑向下排列。这里决定命名、图片职责、布局和进度；服务操作由当前 `sealseek-media` Skill 承接。

## 1. 准备本轮画板

先通过入口依赖、登录和模型能力检查，完成本轮生成参数 dry-run，再创建画板。用户只要求看图或规划时不创建；明确开始生成或批准生成后，每个新的生图任务新建一个画板，同一任务的多张图片共用它。恢复中断、查询旧任务及继续本轮时沿用已记录的画板，不重复创建。

实际看用户图片，按“商品或视觉主题＋本次用途/特点”取一个好记的简短中文名称，例如“蓝兔抱枕·柔光详情页”“云朵沙发·主图焕新”。使用能确认的内容，资料不足时用任务用途命名，不编造品牌或型号。用户指定标题时使用指定值；同名任务可加短日期或简短序号区分，不用原始文件乱码或长任务 ID 作标题。

通过已核验的媒体 CLI 读取当前 `references/cli.md` 中 Canvas operations and placement、Native Frames, explicit batches and existing-media metadata 合同。调用 `canvas create --title 名称 --submit --json`，保存真实 `canvas_id`、名称和链接，使用 `canvas get ID --json` 核对后才开始实际生图。画板创建失败或结果不明时暂停；检查已有记录及 `canvas list`，确认同一次创建的结果，不盲目再建一个。

在当前任务的本地项目目录保存进度：稳定的 `run_id`、画板 ID/名称/链接、源图路径及对应关系、有序行清单、任务 ID、上传 URL、实际尺寸、批次 JSON、每行写入状态和下一行 top。敏感参数与私人路径仅留本地；写前检查路径，已有进度读取恢复，已有用户文件保留。新任务用独立目录和新的 run_id。

## 2. 每生成一张，插入一对图片

按用户约定顺序逐张执行，每个任务请求一张图片。生成命令明确传入本轮 `--canvas ID --archive none`，先 dry-run，通过后按已授权范围提交。`none` 用于在结果实际尺寸确定后成对归档，服务生成历史仍属于该画板；后续步骤会实际插入成图。每张保存并跟踪其任务 ID，成功后获取可用 URL、本地文件及实际尺寸。

左侧原图是这一张成图对应的用户待转换源图，不是内置品牌案例或人物卡。同一原图生成多张方案时，每一行各插入该原图与对应成图。多张源图按既定配对关系逐行处理；确需多张源图共同生成且无法确定主要对照图时，先明确主要源图。

使用媒体 CLI 的 `image upload FILE --submit --json` 上传左侧原图，并通过其当前的实际尺寸检查合同取得原图及成图宽高。已成功上传且文件哈希未变的同一原图复用 URL，画板上仍按每行分别显示。成图使用同一任务已返回的 URL，不为排版重新生成或重新压缩图片。

每完成一张立即计算这一行并成对插入，再处理下一张：

- 左、右各预留宽 480 个画板单位，列间距 24；右图显示宽 480，高度按其实际比例计算。
- 原图等比完整放入左侧的 480 × 右图显示高度范围，顶部对齐并在左列水平居中。由画板显示缩放保持原图完整与成图紧邻，不拉伸、裁切或拼成一张图。
- 第一行 top 为 0；下一行 top = 本行 top + 右图显示高度 + 32。这样每张成图紧接上一张成图下方，原图也不会侵入下一行。
- 左右两图始终是两个独立图片元素，保持原始 URL 和分辨率。生成详情以媒体包支持的隐藏 generationParams 保存，不往图片里添加文字。

使用本应用 CLI 的确定性布局命令 `cloud-hug-style-transfer canvas row --input ROW.json --json`，套件安装可经其 `component run cloud-hug-style-transfer` 入口调用。它只读输入并返回布局，不创建画板、不上传或生图。输入示例：

```json
{
  "run_id": "stable-run-key",
  "row_index": 1,
  "top": 0,
  "source": {"url": "https://example.com/source.png", "width": 1200, "height": 1800},
  "result": {"url": "https://example.com/result.png", "width": 1200, "height": 1800}
}
```

实际输入使用上传和任务返回的真实 URL 及实测尺寸。成图可提供 `generationParams`，仅选用媒体包当前支持的提示词、模型、画幅、参数及参考 URL 等生成详情字段，不复制凭据、请求头、私人路径或完整任务内部记录。

把返回的 `batch` 单独保存成批次 JSON，先执行媒体 CLI `canvas batch ID --file BATCH.json --json` 验证，再加 `--submit` 写入。稳定元素 ID 包含 run_id、row_index 及 source/result，重复执行同一批次具有幂等性。要求写入结果 verified，并回读同一画板核对这一对的 URL、位置、比例和两图数量；确认后才记录 next_top 并进入下一行。

## 3. 恢复与验收

单张失败保留前面已完成的对照行及当前任务 ID；后续恢复从该行继续，顺序不变。归档失败或写入结果不明时，保存结果文件和原批次，先 `canvas get` 核对稳定元素 ID，再依据媒体包恢复合同修复同一批次；不要以新元素 ID 绕过冲突，不用默认网格重排，也不通过 `task sync` 的默认追加另插一份成图。已有人为移动、删除或并发改动时暂停并报告差异，不自动恢复被删元素或移动旧行。

完成标准：画板名称与当前主题/用途匹配，全部约定成图按顺序形成左右对照，每行左原图、右成图，成图上下间距 32、左右列间距 24，比例正确、无重叠和重复项，实际写入已核验。交付独立图片与验收说明时同时给出画板名称和真实链接；未成功成对归档时明确报告未完成部分。
