# 产品识别、设定卡与统一确认

## 产品的三个计数

1. **形态数**：轮廓、造型或关键结构不同的款式。兔与狗是两种形态；同一月亮的紫色和绿色是一种形态。
2. **款色数／卡片数**：每个形态内的各个已识别配色组合，一组合一张卡。纯光线差异、同品重复照片、场景中同款多只不产生新卡。
3. **展示模块页数**：07–10 这一组按形态数生成，每种形态一页。其余页按页面映射完成本轮产品表达，不按卡片数机械复制。

尺寸不同但形态相同时，先记为规格；若轮廓比例显著不同、是否同组影响出图，在统一确认里明确。场景里的普通靠垫、毯子、家具不算在售商品。

## 先判断已整理资料的商品范围

输入可以是用户整理好的多角度商品实拍、旧详情页或两者组合。只有实拍时，按已有款色说明和可见外观判断范围，直接进入多视角依据与产品卡制作，不要求补一套旧详情页。下述页面叙事判断用于确有旧详情页的情况；独立人货比例照片的职责见 [产品尺度](product-scale.md)，不默认混入卡片外观输入。

先枚举并实际浏览整套旧图，再放大与商品范围、轮廓、结构、配色及材质判断有关的画面。总览缩略用于理解叙事，清楚原图用于辨认细节。图片无法读取时记录缺口并尝试允许的读取方式；未成功查看不能记为已查看，缺口影响关键判断时再向用户说明。

识别各页承担的作用：本品首屏、卖点／使用场景、商品特写、款色选择、店铺／系列总览、关联推荐、通用参数或价格说明。**整套图中出现过的商品，不自动等于本次需要升级的商品。** 综合主角、连续展示的使用关系、文字指向、明确的本品款色及用户说明，先得到本轮范围，再统计形态和配色。

- 用户明确清单优先；否则首屏与多个独立卖点／场景形成的商品叙事是重要依据，不能被一张商品总览直接覆盖。
- 店铺总览和关联推荐不自动扩充本轮范围；其中与本轮商品对应的格子仍可提供辅助外观依据。不得仅因某页是宫格就排除其全部内容，也不能把任何款色表都当店铺推荐。
- 不按出现次数投票。只出现一次但有明确本品款色／规格依据的颜色仍应纳入；同款重复摆放、道具和推荐商品不因此变为本轮款式。
- 证据充分时直接给出范围结论并准备卡片。真正无法判断某款是否属于本次、且影响卡片数量时，先完成已有分析，再通过原生问答工具问一个必要的范围问题。不要把可自行判断的整套商品清单交给用户重新筛选。

典型判断：首屏、连续卖点及后续产品展示均围绕白／棕小熊，只有一张混合总览出现兔、河马和狗；在无相反本品清单的情况下，应识别小熊一形态两配色，总览其余商品不自动纳入。这个结论来自全套内容，不能把“只做小熊”或某个页码写成其他任务的默认值。

## 建立简短识别记录

使用稳定的 `group_id` 和 `variant_id`，例如 `moon`、`moon-green`、`moon-purple`。简短记录：

| 记录 | 用途 |
| --- | --- |
| 各页作用、本轮纳入／排除的商品及理由 | 区分主推对象与店铺总览，说明本轮范围如何得到 |
| 形态名、配色名、来源图片 | 让用户能核对每个判断，避免漏款与重复 |
| 整体比例、轮廓、部件位置、纹理和标识 | 约束后续卡片与摄影 |
| 可见依据、合理补全部位、尚有歧义 | 区分直接观察与重建设定 |
| 卡片路径、版本、用户确认状态 | 后续只传入最终认可版本 |
| 卖点／使用场景及来源 | 提供 12 页讨论基础，不提前定四格动作 |

不要根据内置历史系列默认四款六色、法兰绒、PP 棉或旧尺寸。实际查看用户图片，不能只按文件名认款。若有明确商品清单或用户更正，以其为先并指出与旧图的冲突。

详细记录放入本轮项目文档，用户界面只给简短结论、必要图片和问答卡。用户纠正 Agent 的误识别时，记录为识别纠正，不把原本错误的范围描述成用户临时缩减需求。

## 为每个款色选择并实际传入多视角依据

从本轮商品实拍或旧资料选择能够互相补充的清楚画面，按可用资料覆盖：整体长宽与头身比例、头脸／五官、侧背／四肢尾部、面料纹理及本款颜色。**有多个有效视角时，必须选择并实际传入互补参考，不能只用一张总览裁图让模型补出全部角度。** 不硬凑固定数量，不把同一视角的重复图当互补信息，也不无差别传入整套页面。

可以裁取目标商品以减少人物、文字和其他商品干扰，但保留需要判断的整体轮廓、接触结构和有效清晰度；保留原图与裁图对应关系。不能因为某张是无人小图就优先于其他清楚的商品画面，不能把小图放大当作新增细节。原图里虽有人物但可辨的商品部位仍可用，明确人物／场景不迁移。

各来源不一致时，先对照清晰度、遮挡／透视、光线及与其他本品图的吻合程度。对商品外观优先采用清楚且互相支持的本品依据；单张低清总览、风格化示意或泛称材质文字不能覆盖多张清楚的纹理和结构。若仍有影响造型／面料／颜色的实质冲突，通过按钮展示候选解释或参考选择再确认，不能把冲突图片混合成平均外观。

每款色建立有序参考清单，注明各图负责约束什么、哪些内容不迁移。确需借同形态另一配色补结构时，明确只借结构，颜色仍以目标款色依据为准。卡片拼版样例只负责版式。提交时核对实际传入列表与清单一致：**Agent 自己看过图片，不等于生图模型已经收到图片。** 按当前工具参考上限保留有用的互补依据；若资料实际只有一个有效视角，记录这一限制，仍可按下文合理补全，不声称使用了多视角。

## 产品卡样式与生成

卡片样式原图已包含在本包：

- `assets/products/dog.jpg`：横向多图拼版，整体侧面、不同观察方向、头脸与纹理细节。
- `assets/products/rabbit.jpg`：整体轮廓、背面／尾部、头部和面料近摄。

它们对应本次用户提供的示例表达。只学习拼卡与观察方式；除非当前确为同款，不把示例动物的形态、颜色、鼻眼、长条比例或面料作为当前商品依据。

每张卡只展示一个款色，默认横向 6–7 个互补视图：至少有可识别整体形态的视图，再分配侧背、关键结构和材质近摄。格数按可辨识性适度调整，不为凑格数臆造配件。视图之间保持同一轮廓、比例、结构与颜色，用干净中性浅背景、柔和清楚的光线和细分隔；无需人物、标题、品牌标语、尺寸线或未经确认的数值。

通过当前 ToAPIs 的参考图生成能力制作**一张完整拼卡图片**。实际输入上一步选定的有序商品参考，必要时附示例卡并明确其仅负责拼版；无需当前模特卡和整套品牌详情页。提示词保留参考可见的具体外观，不用“圆耳、长圆柱、羊羔绒”等泛化标签替代真实比例、五官形状与纹理。工具支持的比例、参考数量和实际分辨率以实时合同为准。卡片属于前置产品资料，与详情页单独计数：每款色先一张；即使用户明确要求详情页多个备选，也不默认出多套卡。

已有用户制作的合格卡片时可直接采用并核对，避免无意义再生。来源提供多种颜色而确认清单只需部分颜色时，按明确范围制作。

## 无实物与生成补全

允许根据旧图生成未展示的角度、遮挡部分及合理结构；不以“没有实物”或“缺少背面照片”自动阻塞。**合理补全只用于资料缺失之处，已有清楚依据的部位应尽量保留。** 保护已知轮廓与部件，采用与现有证据相容的补全，简要标明例如“背部接缝依据可见结构补全，请确认”。无法区分到底几款／几色、或已有图存在未解决的实质矛盾时，通过原生问答工具先问最少的关键问题，避免为猜错款色付费。

卡片旁保留补全说明，不把它写成实拍已验证。用户确认后，该卡是本轮视觉制作认可的产品设定；以后用它约束造型、颜色和材质外观。用户也可自行修图、重画或上传替代卡，沿用同一 `variant_id` 更新版本。保留旧版本，不混用未确认的新卡。

视觉卡片不能自动确立材料成分、具体尺寸、载荷、认证或医疗功效。这里不生成参数页面，16–19 仍由同事处理。

## 生成后先对照原图验收

实际打开生成卡及选定的原始商品依据，检查：

- 整体轮廓与头身比例、头脸／眼鼻／耳朵的位置和形状、前后肢及尾部是否接近可见原图；不只检查“还是一只熊”等类别特征。
- 本款颜色、绒面颗粒／卷曲的大小和方向、起伏与光泽是否接近；不能把明显的大块卷曲统一改成细密颗粒绒，或把有依据的鼻部质感改成通用玩具造型。
- 同一卡各视角能否解释为同一件商品；同形态各配色是否保留应当一致的结构。没有依据时，不能一色有后脚、另一色没有；真实存在的结构差异则保留。
- 每个新角度中哪些部分来自原图、哪些属于补全；卡内能否清楚辨认整体和关键部件。

先排除透视、受力与光线造成的合理差异，再判断外观偏离。图像精美、拼版整齐或生成成功不代表产品接近。发现明显偏差时定位参考选取、传入缺失或提示词原因，在已授权范围内修正对应卡；需要额外付费且未获授权时用问答工具说明问题、范围和费用并等待选择，不无限重生。尚未修正的明显偏差不能标为合格，也不能交给后续详情页继续放大。

保留精简对照结论和补全部位，不承诺无实物条件下完全还原。卡片通过已知外观对照后，再进入用户统一确认；用户可直接修订或上传替代卡。用户确认不替代 Agent 的这次原图对照检查。

若用户明确指定采用与旧图不同的修订外观，记录其主动调整并以确认版本作为新设定；不要把用户指定的改动误判成未修正偏差。

## 卡片出齐后，整理独立比例依据并集中确认整套范围

产品卡完成后按 [产品尺度与人货比例](product-scale.md) 采用用户指定的尺度图，或从旧资料中选取可靠人货同框图；没有时请用户补充。已有适用图就不再追问尺寸、估算厘米或要求确认数字。旧资料中的真实规格仍保留出处，不作为生图必填项。尺度图独立保存，不拼入卡片、不按配色逐卡配套，不要求再生成一套尺度卡；记录适用产品与来源，前期集中确认时沿用已有明确指定。

展示所有卡片，并用一句可核对的结果开头，例如：

> 本次识别为 1 种月亮造型，绿色／紫色 2 个配色；产品卡 2 张，款式展示模块 1 页。

展示必要的补全部位、独立尺度依据、四宫格四项内容，以及实际页面清单、整套生成张数与当前已核验的费用信息，将“认可这些依据并按此范围连续完成整套”合并在一次确认中。只对缺失或冲突提问；已有明确确认、整套生成要求或自主执行授权直接使用，不重新要求选择生成范围或默认模型。自然语言回答有效，不要求补点按钮、逐卡确认或固定句式；用户未回复不算确认，仅认可一张也不自动认可其他卡。

12 页始终规划四个图片位，但不强求四个互不重复的“功效”。根据用户确认的卖点及用途形成四个明确展示任务；卖点较少时可提出同一卖点的不同使用场景供确认，较多时请用户选重点或认可 Agent 的优先建议。不能自行填入原模板四种睡姿或编造功能凑数。

前期确认齐全后再展开整套详细规划，默认每屏一个方案，随后按已确认范围连续生成每屏一张完整页。记录卡片版本、分组配色、独立尺度依据、四宫格内容和生成范围至 manifest.json，并更新总览。后续沿用这些状态，不因规划完成或切换批次再询问。外观卡修订不自动要求重拍比例照片，尺度适用性按规格与实际变化复核。
