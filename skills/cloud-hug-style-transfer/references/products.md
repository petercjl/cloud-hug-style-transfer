# 产品识别、资产分组与统一确认

## 产品的三个计数

1. **形态数**：轮廓、造型或关键结构不同的款式。兔与狗是两种形态；同一月亮的紫色和绿色是一种形态。
2. **款色数／资产套数**：每个形态内的各个已识别配色组合，一组合一套独立产品资产。纯光线差异、同品重复照片、场景中同款多只不产生新资产。
3. **展示模块页数**：07–10 这一组按形态数生成，每种形态一页。其余页按页面映射完成本轮产品表达，不按资产数机械复制。

尺寸不同但形态相同时，先记为规格；若轮廓比例显著不同、是否同组影响出图，在统一确认里明确。场景里的普通靠垫、毯子、家具不算在售商品。

## 先判断已整理资料的商品范围

输入可以是用户整理好的多角度商品实拍、旧详情页或两者组合。只有实拍时，按已有款色说明和可见外观判断范围，直接进入产品资产图组制作，不要求补一套旧详情页。下述页面叙事判断用于确有旧详情页的情况；资产组的相对尺寸照片的职责见 [产品尺度](product-scale.md)，不默认混入资产外观输入。

先枚举并实际浏览整套旧图，再放大与商品范围、轮廓、结构、配色及材质判断有关的画面。总览缩略用于理解叙事，清楚原图用于辨认细节。图片无法读取时记录缺口并尝试允许的读取方式；未成功查看不能记为已查看，缺口影响关键判断时再向用户说明。

识别各页承担的作用：本品首屏、卖点／使用场景、商品特写、款色选择、店铺／系列总览、关联推荐、通用参数或价格说明。**整套图中出现过的商品，不自动等于本次需要升级的商品。** 综合主角、连续展示的使用关系、文字指向、明确的本品款色及用户说明，先得到本轮范围，再统计形态和配色。

- 用户明确清单优先；否则首屏与多个独立卖点／场景形成的商品叙事是重要依据，不能被一张商品总览直接覆盖。
- 店铺总览和关联推荐不自动扩充本轮范围；其中与本轮商品对应的格子仍可提供辅助外观依据。不得仅因某页是宫格就排除其全部内容，也不能把任何款色表都当店铺推荐。
- 不按出现次数投票。只出现一次但有明确本品款色／规格依据的颜色仍应纳入；同款重复摆放、道具和推荐商品不因此变为本轮款式。
- 证据充分时直接给出范围结论并准备资产。真正无法判断某款是否属于本次、且影响资产套数时，先完成已有分析，再通过原生问答工具问一个必要的范围问题。不要把可自行判断的整套商品清单交给用户重新筛选。

典型判断：首屏、连续卖点及后续产品展示均围绕白／棕小熊，只有一张混合总览出现兔、河马和狗；在无相反本品清单的情况下，应识别小熊一形态两配色，总览其余商品不自动纳入。这个结论来自全套内容，不能把“只做小熊”或某个页码写成其他任务的默认值。

## 建立简短识别记录

使用稳定的 `group_id` 和 `variant_id`，例如 `moon`、`moon-green`、`moon-purple`。简短记录：

| 记录 | 用途 |
| --- | --- |
| 各页作用、本轮纳入／排除的商品及理由 | 区分主推对象与店铺总览，说明本轮范围如何得到 |
| 形态名、配色名、来源图片 | 让用户能核对每个判断，避免漏款与重复 |
| 整体比例、轮廓、部件位置、纹理和标识 | 约束后续资产与摄影 |
| 可见依据、合理补全部位、尚有歧义 | 区分直接观察与重建设定 |
| 资产路径、版本、用户确认状态 | 后续只传入最终认可版本 |
| 卖点／使用场景及来源 | 提供 12 页讨论基础，不提前定四格动作 |

不要根据内置历史系列默认四款六色、法兰绒、PP 棉或旧尺寸。实际查看用户图片，不能只按文件名认款。若有明确商品清单或用户更正，以其为先并指出与旧图的冲突。

详细记录放入本轮项目文档，用户界面只给简短结论、必要图片和问答卡。用户纠正 Agent 的误识别时，记录为识别纠正，不把原本错误的范围描述成用户临时缩减需求。

## 调用 product-asset-set 制作资产并返回

识别完成后按 [产品资产交接](product-assets.md) 加载并执行当前 `product-asset-set`。传入本轮实际原图、已确定的形态配色、用户指定基准和授权边界。资产制作策略、独立图片规划、逐张验收和修订由 callee 负责，本 Skill 不重复维护一份拼卡提示词或制作流程。

每款色交接一个版本目录及 `资产说明.txt`。校验后实际查看全貌、尺度、材质和按需结构资产，与原始商品对照；用户已确认的同一版本直接复用。记录补充证据的局限，缺少来源的生成细节不能当成商品事实。

资产阶段结束返回前期集中确认：展示形态配色、每套资产用途与独立张数、适用尺度依据、12 页四格内容和整套范围。每款色一套资产，不再按“每款色一张卡”计算费用。07–10 按形态分组，详情页数量保持原有规则。资产确认不等于授权详情页生成。

旧项目可保留原产品资产图组和历史记录，但新任务按资产交接合同建立依据；旧卡不能自动算作三项独立资产已完成。用户要求沿用旧依据作探索测试时保留真实状态与授权来源，不将探索结果标为正式资产验收通过。
