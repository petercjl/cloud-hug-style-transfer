# 用户反馈后的诊断、修订与再生成

触发：用户指出某张成图的问题，或要求依据反馈修图。此分支承接当前图片审核与用户确认节点，完成后返回同一张图的确认节点。

输入：用户反馈与指向区域、当前页/资产和attempt、真实成图、实际请求全文、实际有序参考及职责、已确认要求、现有任务状态与本次授权。
输出：可追溯诊断、必要的新规划/参考与完整英文提示词、知识库复查回执；已授权时生成一次当前修订结果及双语审核HTML，然后等待用户确认。

## 1. 定位反馈与实际证据

把用户问题绑定到具体页、attempt与区域。实际打开原生结果和本次传入的参考图片，核对实际提交prompt、图号、参考顺序、职责、哈希和参数；规划稿不代替request。用户圈选和文字是定位依据，缺失文件、未观测区域和隐藏结构保持未知。先保留原请求、成图、旧报告与用户决定。

进入本知识节点时按需读取知识结构、入口和近期记录；产品身份或动作问题读取 [产品结构与动作适配](../topics/product-identity-and-pose.md)，道具位置、支撑或地面问题读取 [物体承托与空间边界](../topics/support-and-spatial-boundaries.md)。仅加载当前问题相关主题；修订完成后再进入完整的提示词检查。

## 2. 诊断最早失效环节

| 分类 | 检查与处理 |
| --- | --- |
| 提示词遗漏或冲突 | 指出实际句子、缺失关系或相互冲突指令，修改对应场景表达 |
| 参考错误或歧义 | 查看真实图像是否错款、职责冲突、图号错配或角度证据不足；调整选图和交接，必要时请用户明确基准 |
| 构图或动作不可行 | 检查原产品能否按现有形态放入场景，调整人物姿态、承托、机位或遮挡 |
| 模型执行偏差 | 指令与参考已有清楚依据，成图仍未遵循；记录为执行偏差或原因待定，不能凭一次失败宣称模型固有能力不足 |
| 证据不足/混合原因 | 分开记录已观察错误与原因假设，补查证据；会影响修订方向的未知项向用户简短澄清 |

一个问题可涉及多类。用户确认的问题是验收反馈，单次成图不能证明唯一原因；不能为了给出解释而强行把问题归为提示词错误。

## 3. 向用户反馈诊断与修订方向

先简短说明：发现了什么 → 对应哪句prompt或哪张参考 → 判断与不确定性 → 准备改什么、保留什么。避免整段复述全部提示词。用户已明确要求修图或重新生成且依据齐全时，反馈后继续执行，不例行重复请求批准；仅要求检查/分析时止于诊断，用户要求改词时交付新词与复查结果，均不自动生图。参考基准仍有实质冲突时停在该项澄清节点。

## 4. 局部修订与知识库复查

保存新的完整英文prompt与中文翻译，必要时更新受影响的规划和参考顺序。保留用户已确认且与本问题无关的产品、人物及画面要求；修订正文直接表达当前目标，纠错历史单独保存在项目。使用原始/已确认资产作为事实依据，失败成图不升级为产品身份依据。

按集中检查入口 `review-planned-prompts.md` 的合同，对最终实际prompt和有序参考自检。prompt、参考或适用知识变化使旧pass失效；needs-revision继续修词，unknown补证据。检查pass不代表成图通过。

若最早失效节点是产品资产，按主Skill的product-asset-set交接合同返回资产修订与用户确认；资产变化使依赖确认与详情规划失效。修订通过后只重跑受影响下游，已确认且无关的页面复用。

## 5. 当前页再生成、审核与返回

当前明确修图/重生授权覆盖本页一次新尝试；不自动连续付费重试。提交前恢复本页运行中或未知任务，不重复创建。按media-execution.md核验模型、参数、选图及授权，再通过原有ToAPIs执行路线提交新attempt，保留旧attempt。批量反馈只处理用户指定范围，仍遵守最多5个在途任务。

结果完成后实际看图：重点复核用户指出的问题，同时检查修订是否引入产品、尺度、人物或空间新错误。即使未修好也保存真实结果与问题；通过aigc-generation-review制作当前attempt审核HTML，包含实际有序参考、逐字英文prompt及其中文翻译、参数、结果和事实观察。报告失败只恢复报告节点，不重生图片。

逐张修订展示图片、报告和简短结论后，置为awaiting-user-confirmation，awaiting_user=true，清空当前可提交范围并结束本轮。批量修订结束后统一报告，等待对受影响结果的确认。用户认可修复只更新其明确覆盖的维度；不推定整图接受或授权下一页。仍有问题则回本分支，新的付费尝试须在用户明确授权内。

## 项目记录与知识演进

沿用项目清单，新建版本化feedbackRevision记录：pageId/assetId、previousAttempt、feedback与区域、已确认维度、实际证据路径/哈希、diagnosis分类、observations、hypotheses与未决问题、修订范围、复用部分、promptRevision、promptReview路径、本次授权范围、newAttempt/taskId、报告和userDecision。实际知识读取文件及哈希保存在promptReview中。维护状态包括diagnosing、needs-clarification、revision-ready、generating、report-pending、awaiting-user-confirmation；外部任务状态与业务验收状态分开。

只使受影响结论和下游失效；旧请求、旧诊断、失败图和审核历史保留。查看记录不修改用户确认。项目记录保存在项目内，不进入公开包。

将可复用发现先记为知识候选；经用户授权维护时脱敏写入主题，记录U/E/A来源、适用范围、局限与版本，并更新入口及来源记录。一次成功修订是案例证据，不是通用成功保证；普通运行不自动修改安装中的Skill。
