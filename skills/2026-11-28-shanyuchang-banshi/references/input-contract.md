# 调度与版式的本地交件约定

在项目目录提供 UTF-8 的 `project.json`。照片和旧图可在项目的子目录，也可引用现有本机目录。图片键与数组次序定义角色，文件名可按下例交件或显式改为实际名称。调度交原图、商品编号、色名与张数，旧模块识别和贴图复核由版式执行助手负责。

```json
{
  "product_id": "1100000000000",
  "colors": ["雪白", "夜黑"],
  "photos_dir": "摄影",
  "old_dir": "旧详情页",
  "photos": {
    "hero": "首屏.png",
    "multicolor": "多色整屏.png",
    "sport": "运动.png",
    "banners": ["横屏01.png", "横屏02.png", "横屏03.png"],
    "brand": {
      "雪白": ["雪白01.png", "雪白02.png"],
      "夜黑": ["夜黑01.png", "夜黑02.png"]
    },
    "closing": "收尾.png"
  }
}
```

| 文件角色 | 验收口径 |
|---|---|
| hero | 完整无字竖照。以全宽换算至 1500 px，交人物最高点、底部关键部位和顶区背景目检，见[首屏留位规格](首屏留位规格.md)。|
| multicolor | 按色数和排格交完整有字成品，以原画幅按宽 1500 等比放大。单色款省略。|
| sport | 无字运动竖照一张，常见 4:5、3:4 或 2:3。|
| banners、closing | 无字 3:2 横照。展示组可配 2–3 张，收尾独立一张。|
| brand | 按准确色名分组的无字竖照，通常 2:3 或 3:4，每色可配 2–3 张。数组内次序即摄影次序。|

`colors` 始终按多色格从左到右。可选 `settings` 示例为 `{"horizontal_count":2,"per_color_count":3,"color_order":"reverse","frames":{"mode":"first_full"}}`。色序可填 `same`、`reverse` 或完整色名数组；只影响每色摄影段。默认值集中在 `assets/layout.json`。每色品牌摄影的装饰标识固定在顶部原位，三组文字与模板边距一致。相框模式固定为 `first_full`。每色首张四边为零，后续张带框，每个色组独立。框宽和组内上下白带读同一配置。可选 `settings.showcase_title` 为布尔值，默认开。下游在细节后、每色摄影前找本款实拍展示标题片，有则按原比例放入，缺时登记「旧页未找到」并跳过。

## 一条命令与返回值

```powershell
python -B -X utf8 "<skill>/scripts/build.py" "<项目目录>" --output "<独立输出目录>"
```

省略 `--output` 时生成项目的同级目录「项目名_版式输出」。先汇总输入文件、数量、画幅、色名、目检数据与输出路径问题。输出不能是项目输入根或其上级，须保护专用照片、旧页和 skill 素材目录。如果用项目根扫描旧页，允许根内独立交付并从扫描中剪除该输出子树。重跑只替换自己记录且未经外部修改的文件，保留其他内容。无需安装依赖或联网。

- `切片/商品编号详情页_01.jpg` 起，按内容顺序编号，每片宽 1500、高不大于 2500、质量 92、内嵌 sRGB。
- `整页预览.jpg` 为宽 750 的整页。超出 JPEG 长边上限时返回同名 PNG。
- `交付清单.md` 每个物理屏一行，给出来源、贴图位置或补位理由、标红状态，并记录色序来源及本次实际色名。
- `项目记录/定位/NN.jpg` 为每张贴图的红框预览；`项目记录/排版数据.json` 保存来源、候选分数、坐标、选用色序及每片的整页半开区间。坐标原点在各屏左上。正式切片没有红框。
- 退出 0 表示所有可见屏已有切片，也可能有设计待确认项。退出 3 表示完成其余屏、存在没有安全切线的可见模块。退出 2 表示输入或输出保护检查未通过。上架前以清单及完整覆盖状态为准。

## 执行助手的目检记录

在本次项目的独立工作记录里保存 JSON；调度不必提供。用 `--review "<记录路径>"` 指定，或在 `project.json` 的 `review_file` 引用。输入目录仅供读取，该 JSON 应放在发布输出以外。项目记录由助手维护，过程无需询问使用者。

`modules` 是可选数组。每项可给非负整数 `order` 表示在原页的先后；各细节模块应统一给出或统一按自然文件序及原片行序登记。每项含 `kind`、`safe: true`、`evidence` 和按**原顺序**列出的 `parts`。每段含当前旧页的 `file`，可附原图纵向半开区间 `rows`；`windows` 为在原图中目检过的整行可切带列表，均用原图像素。跨片模块列多段；同类可登记多个独立候选。例：

```json
{"modules":[{"kind":"detail","safe":true,"evidence":"标题接两个拉链局部，下一片接防雪裙，图文完整","parts":[{"file":"部件上.jpg","windows":[[840,875]]},{"file":"部件下.jpg","rows":[0,990],"windows":[[12,30]]}]}]}
```

`photos` 为可选的目检字典，键为 `hero`、`sport`、`banner.1`、`brand.雪白.1`、`closing` 等。每项绑定实际文件的 `sha256`。在未贴底片上用 0–1 坐标的 `protected: [[左,上,右,下]]` 登记脸、手、衣服关键结构及器材。可用 `reject: {"original":"英文压雪镜"}` 记录目检否决，位置名还有 `swap_x`、`swap_y`、`swap_xy`。旧目检文件里的逐照片 `frame` 字段不再改变色组框。额外遗留问题记入 `issues`。打开最终红框后填 `checked: true` 及对应 `checked_boxes`（从排版数据复制 `boxes`）；更换底片或候选框时重新复核。固定顶部的每色摄影只做成图内容总览。

标识保持原字形、色彩、尺寸和组内相对位置。先试原位，再用同边距换边。顶、底以照片可见内缘为基准，左右以 1500 页面为基准。每色品牌摄影固定原顶部，不读避让参数、评分或框位置复核；仍生成红框，摄影内容问题照常记录。对需要避让的槽位，脚本逐块测平均亮度、笔画覆盖背景的白字对比度第 25 百分位、以及边缘密度，保留各候选指标。所有候选都不合格时，以综合代价最低者出图并标红。

本地默认阈值按标准款照片校准。取标准图标识框中未被 alpha 覆盖的背景，运动两组的对比第 25 百分位约 1.95/2.06，第二横幅约 1.82，白色第二张三组约 1.84/1.79/1.72。配置以 1.72 为白字对比下限，另检区域平均亮度及纹理。收尾浅蓝底约 1.57，按当前规则仍须标红。数值衡量本套摄影底色，不代替对主体压盖的目检。


详情页角色、顺序、数量来源和画幅由 `assets/layout.json` 的 `slots` 给出。单张读取 `count`，展示组读取 `count_key` 指向的设置，每色组对每个实际色名分别展开。多色条件和可选旧标题在各槽定义中标注。旧标题的目检类型为 `showcase_title`，仅分给该槽位。详情页透明贴图原宽须为 1500 px。

## 子目录与混排旧图

输出可放在项目下的独立子目录。扫描旧图时排除本次输出整棵目录与独立摄影目录。输出不能等于项目、包含项目或覆写专用来源目录。所有输入图片以文件内容解码。旧页混排时，先读工作副本的纵向半开区间。记录模块自然边界、内容类型和画质。整屏保留原品牌、文字与图标。可将一项安全模块的 `slots` 限定为有内容依据的槽位。尺码表仅有成衣尺寸时登记字段和单位；不得将其称作身高体重推荐。

当商品根只读时，可用 `build.py "<商品根>" --manifest "<工作子目录>/project.json" --output "<新版>/详情页成品"`。清单内的相对路径仍从商品根解析；目检文件位于发布目录之外。

## 新首屏与多行整屏的目检字段

`slots` 中首屏的 `aspect: "portrait_clearance"` 表示竖幅按净空验收，多色的 `"color_grid"` 表示排格决定整屏画幅，其余镜头沿用比例列表。首屏测量绑定实际 PNG 的 SHA256，在 `photos.hero.reserve` 填 `{"top":340,"bottom":210,"clean_sky":true}`。单位为完整原片 px，top 是最高人物或装备距顶，bottom 是脸、手、口袋、腰带、拉链中最小的离底距离。脚本自动换算至 1500 宽并对照阈值。未测、净空不足或顶区背景不合适均登记待确认，保留原图。雪靴和杖尖可进入底部保护带。

每张图可在目检对象的 `observation` 填总览结论，随对应槽位进入交付清单；需设计师确认的具体问题放入 `issues`。超高多色整屏在 `photos.multicolor.cut_windows` 填原图坐标下两格行之间已目检的全宽空带 `[[y0,y1], ...]`，`checked: true` 表示已核对该屏。切线还需通过全行近纯色检查。

## 旧信息屏的归属

先登记每项的原始类型。细节标题与全部细节项按原顺序交给 detail，保留部件标签、原品牌和出处。一项不能同时占两个槽。证书只用报告或同性质检测证据，尺码用本款实际的推荐或尺寸表。补位只能使用性质相近、未归其他槽位的完整模块，例如穿衣分层说明补材质。经目检的 `other` 须以 `slots` 指明唯一合适的目标并说明依据。原先借给证书的裤脚抽绳等归回细节；证书无合适来源便省去，其余旧信息槽同理。清单保留该行，以「旧页无此类模块，已去掉」记通过，不占页面高度。可选实拍标题缺失另记「旧页未找到」。超长细节集合可在完整图卡之间切片，单卡超长仍需安全空带。

## 主图、搜索图、SKU

同一 UTF-8 项目清单复用 `product_id`、`colors`、`photos_dir` 及可选 `old_dir`。下面是双色的 `commercial` 对象。索引是字符串，每个文件名均相对摄影目录。

```json
{
  "main": {"1":"主图_1.png","2":"主图_2.png","3":"主图_3.png","4":"主图_4.png","5":"主图_5.png"},
  "search": {"1":"搜索图_1.png","2":"搜索图_2.png","3":"搜索图_3.png","4":"搜索图_4.png","5":"搜索图_5.png"},
  "sku": {"雪白":"SKU_雪白.png","夜黑":"SKU_夜黑.png"},
  "review": {}
}
```

单色省略主图键 `2`，其余索引保留原编号。每色一张 SKU，搜索图四张主色、一张辅色。主图 2、3、5 均交模型生成的带字整屏，摄影交无字原片。每张的总览结果放在 `commercial.review[来源文件名]`，含真实原片的 `sha256`、`note` 和 `status`（通过或待设计师确认）。未填写的项记为待设计师确认。

```powershell
python -B -X utf8 "<版式skill>/scripts/build_commercial.py" "<商品根>" --manifest "<项目清单.json>" --output "<新版根>"
```

尺寸与模板从 `assets/layout.json` 的 `commercial` 读取。输出为 `04_主图/`、`05_搜索图/`、`06_SKU/`、`主图搜索图SKU总览.jpg` 和 `主图搜索图SKU交付清单.md`。整屏原样缩到目标尺寸。摄影等比盖满、中心裁切，模板在 (0,0) 原像素整张叠放。清单以原片半开坐标登记裁框及面积损失，超过 2% 单列。输出目录可与其他交付共存；发生同名且不属于本脚本的文件时停止发布。
