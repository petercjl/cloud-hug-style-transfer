# 山与场版式

收件格式见 [input-contract.md](references/input-contract.md)。首屏的上游摄影要求见 [首屏留位规格](references/首屏留位规格.md)。两个本地脚本共用 Python、Pillow 和 numpy。页面文案来自原图、整屏或透明 PNG。

## 详情页

1. 按多色屏的格序登记色名。读本款上游交付清单，选择实际可用版本；按调度的影像验收记录选用本款底片。横幅张数、每色张数、色序、白边和可读性阈值的默认值集中在 `assets/layout.json`。
2. 按[旧模块识别](references/旧模块识别.md)查看当前款旧页及相邻片。两套样本可由内容指纹自动识别。新款中未收录的原图由执行本 skill 的助手本地看图、登记完整模块与安全空带。保护人脸、手、关键衣片和器材；记录在本次项目的目检文件中。卖点、材质、证书、细节与尺码先用同类模块；仅可用性质相近且不归其他槽的剩余完整模块补位，写明依据。细节标题及全部细节项按原页顺序合成一屏，原来借给证书的裤脚抽绳应归回细节。经确认的穿衣分层说明可补材质。没有合适来源就删除这整屏，清单记「旧页无此类模块，已去掉」，状态通过，页面高度为零。
3. 运行 `python -B -X utf8 "<skill>/scripts/build.py" "<项目目录>" --output "<交付目录>"`。顺序为首屏、多色、卖点、运动、材质、证书、横屏、细节、实拍展示标题、每色摄影、收尾横屏、尺码。单色跳过多色；实拍展示标题受开关控制，旧页找不到就登记并跳过。每色首张满幅，其余带框。每张均把「每色品牌摄影.png」固定在原顶部，满幅和相框里的页边距沿用配置。收尾紧随最后一色。
4. 每张详情摄影均保留红框预览。每色摄影的装饰标识直接贴在顶部原位，跳过亮度、对比、压帽和位置复核；摄影本身的偏差仍进清单。运动、展示横幅与收尾横幅在候选位置检查亮度、白字对比和边缘密度。助手补充保护区或目检否决理由，复跑后核对最终框坐标，再把目检结果随项目保存。所有位置均有问题时保留最佳候选，标红「标识位置待设计师确认」。首页上下两组固定，照片保持完整。首屏按宽 1500 的实测净空检查，多色屏按格数规划的原画幅等宽交付。摄影结果集中目检，一张一次，偏差写入清单。
5. 查 `交付清单.md` 与 `项目记录/排版数据.json`。补位标红并注明来源和原因；超高模块没有安全切线时，该模块仍进长预览，其余模块正常出片，清单注明缺口。详情页透明贴图宽度必须为 1500 px，按原像素贴，尺寸错误须指出文件名。

逐张白边、参考款标识位置及统计口径见[白边实测](references/白边实测.md)。页面结构参考依次为 `assets/reference/01_首屏多色.png` 至 `08_尺码参考.png`。这些缩略图只用于认结构。
项目内的交付子目录从输入扫描中排除。读旧图按内容识别格式；按内容类型、可读画质和自然边界挑选原模块，品牌标志与图文整体原样保留。

成品验收运行 `python -B -X utf8 scripts/verify_frames.py "<交付目录>"`。该检查重新读 Markdown 色组和交付 JPG 的白边。

## 主图、搜索图、SKU

按[商业图字段](references/input-contract.md#主图搜索图sku)准备清单。在授权的新版根目录运行一次即可装配三类图。

```powershell
python -B -X utf8 "<版式skill>/scripts/build_commercial.py" "<商品根>" --manifest "<工作清单.json>" --output "<新版根>"
```

主图 1、4，全部搜索图与 SKU 先用 LANCZOS 保持比例盖满画布，再居中裁切，整张模板按原像素贴在 (0,0)。每个模板画布必须与配置相符。固定角标不做避让。主图 2、3、5 完整缩放到 1440×1920，保留全部内容。搜索图与 SKU 成品为 1440×1440。交付三个分类目录、三行总览和逐张清单，裁掉超过 2% 时注明原片裁框。
